# อีเมลแจ้งเตือนใบอนุญาตรายสัปดาห์ (Weekly Alert)

ระบบสรุปใบอนุญาต **นำเข้า (Import License)** และ **นำออก (Export License)** ที่ต้องดำเนินการ
แล้วส่งอีเมลออกเองทุกสัปดาห์เข้า **Outlook / Microsoft 365** โดยไม่ต้องเปิดหน้าเว็บทิ้งไว้

ผู้รับตั้งค่าเริ่มต้นไว้ที่ `theeparat.metheepooriwat@kobelco.com`

## 1. อีเมลมีอะไรบ้าง

อีเมลวางรูปแบบตาม **หนังสือบริษัทฉบับทางการของไทย** ไม่ใช่หน้าแดชบอร์ดและไม่ใช่อีเมลลำลอง
ใช้สีแค่ดำกับเทา มีแดงเข้มเฉพาะคำว่า “หมดอายุแล้ว” และ “เลยกำหนดยื่น” เท่านั้น

| ส่วน | รายละเอียด |
| --- | --- |
| หัวจดหมาย | โลโก้ KOBELCO ชิดซ้าย ชื่อบริษัทและหน่วยงานอยู่ทางขวาในแถวเดียวกัน คั่นด้วยเส้นคู่ |
| เลขที่หนังสือ | อ้างอิงตามเดือนและลำดับสัปดาห์ เช่น `ที่ IC-2569/09-2` พร้อมวันที่ชิดขวา |
| เรื่อง | รายงานสถานะใบอนุญาตนำเข้าและนำออก ประจำสัปดาห์ที่ 2 ของเดือนกันยายน 2569 |
| เรียน | ชื่อผู้รับ ตั้งได้ที่ `WEEKLY_ALERT_GREETING` |
| เนื้อความ | ย่อหน้าเว้นวรรคหน้า ขึ้นต้นด้วย “ด้วยระบบ I-CONFIRMATION ได้ตรวจสอบ…” แล้วแจกแจงยอดเป็นรายการย่อยแยกตามใบอนุญาตนำเข้า/นำออก |
| ข้อ ๑ | ใบอนุญาตนำเข้า — เลขที่ใบอนุญาต, Invoice, รุ่น, จำนวน, วันหมดอายุ, คงเหลือ, สถานะ |
| ข้อ ๒ | ใบอนุญาตนำออก — Exception License, จำนวน, วันหมดอายุ, คงเหลือ, สถานะ, กำหนดยื่น กสทช., สถานะการยื่น |
| คำลงท้าย | “จึงขอแจ้งมาเพื่อโปรดพิจารณาดำเนินการในส่วนที่เกี่ยวข้องต่อไป ขอขอบคุณเป็นอย่างยิ่ง” |
| หมายเหตุ | ข้อ ๑–๓ ท้ายหนังสือ รวมข้อความว่าจัดทำโดยระบบอัตโนมัติจึงมิได้ลงลายมือชื่อ |
| ไฟล์แนบ | ไฟล์ Excel (.xlsx) รายการทั้งหมด หัวคอลัมน์พื้นเขียวอมฟ้าตัวอักษรขาว แถบสลับสี แถวที่หมดอายุแล้วไฮไลต์ชมพู ตรึงหัวตารางไว้ — ชุดสีเดียวกับไฟล์ที่กด Export จากในระบบ |

สัปดาห์นับเป็น “สัปดาห์ที่เท่าไรของเดือน” โดยยึดวันพฤหัสบดีของสัปดาห์เป็นตัวตัดสินว่าอยู่เดือนไหน
สัปดาห์ที่คร่อมสองเดือน (เช่น 31 ส.ค. – 6 ก.ย.) จึงถูกนับเป็นสัปดาห์ที่ ๑ ของเดือนกันยายน
ซึ่งเป็นวิธีเดียวกับที่มาตรฐาน ISO-8601 ใช้ เลขที่หนังสือก็อ้างอิงชุดเดียวกัน

ยอดจำแนกใต้ย่อหน้าเปิดจะแสดงเฉพาะบรรทัดที่มีจำนวนมากกว่าศูนย์ และประเภทที่ไม่มีรายการเลยจะไม่ขึ้นหัวข้อ
ผลรวมของทุกบรรทัดจึงเท่ากับยอดรวมที่ประกาศไว้ในย่อหน้าเปิดเสมอ

ช่องที่เป็นเลขที่ใบอนุญาต เลข Invoice และวันที่ ตั้ง `white-space:nowrap` ไว้ทั้งหมด
จึงไม่ถูกตัดขึ้นบรรทัดใหม่กลางคำ เช่น `IL-2026-0148` จะไม่กลายเป็น `IL-2026-` แล้วขึ้นบรรทัดต่อด้วย `0148`

ปีที่แสดงเป็น **พ.ศ.** ตามแบบหนังสือไทย เลขลำดับข้อใช้เลขไทย ส่วนตัวเลขข้อมูลใช้เลขอารบิกเพื่อให้อ่านง่าย
เปลี่ยนกลับเป็น ค.ศ. ได้ที่ `WEEKLY_ALERT_BUDDHIST_YEAR=false`

### โลโก้บนหัวจดหมาย

ไฟล์โลโก้อยู่ที่ `backend/assets/kobelco-logo.png` ตั้งค่าได้ที่

```env
WEEKLY_ALERT_LOGO=assets/kobelco-logo.png
WEEKLY_ALERT_LOGO_WIDTH=190
```

รูปถูก **แนบไปกับจดหมายแล้วอ้างด้วย `cid:`** ไม่ใช่ลิงก์ภายนอกและไม่ใช่ `data:base64`
เหตุผลคือ Outlook บนเดสก์ท็อปไม่รองรับ `data:base64` เลย ส่วนลิงก์ภายนอกจะถูกบล็อกจนกว่าผู้รับ
จะกด “ดาวน์โหลดรูปภาพ” วิธี `cid:` จึงเป็นวิธีเดียวที่โลโก้ขึ้นทันทีทุกเครื่อง
ไฟล์ที่ให้มากว้าง 400px แต่แสดงจริง 190px เพื่อให้คมบนจอความละเอียดสูง
บนจอมือถือ โลโก้กับชื่อบริษัทจะเรียงลงมาเป็นสองบรรทัดแทนที่จะเบียดกันในแถวเดียว

หากหาไฟล์โลโก้ไม่พบ ระบบจะเขียน log ไว้แล้วส่งจดหมายต่อโดยไม่มีโลโก้ (ยังมีชื่อบริษัทเป็นหัวจดหมาย)
และถ้าผู้รับตั้งค่าไม่ให้โหลดรูป จะเห็นเป็นชื่อบริษัทจากค่า `alt` แทน
เปลี่ยนโลโก้เองได้โดยวางไฟล์ทับ หรือชี้ `WEEKLY_ALERT_LOGO` ไปที่ไฟล์อื่น

ออกแบบด้วย table + inline style ล้วน จึงแสดงผลถูกต้องทั้งบน **Outlook เดสก์ท็อป (Windows)**,
Outlook Web, Outlook มือถือ และโปรแกรมอ่านเมลอื่น ๆ พร้อมแนบฉบับข้อความล้วนที่จัดหน้าแบบเดียวกันไปด้วยเสมอ

> **ตรวจก่อนใช้งานจริง** ชื่อบริษัทในหัวจดหมายตั้งค่าเริ่มต้นไว้ว่า
> *Kobelco Construction Machinery Southeast Asia Co., Ltd.* โปรดแก้ `WEEKLY_ALERT_ORG`
> ให้ตรงกับชื่อนิติบุคคลที่ถูกต้อง เพราะหนังสือฉบับนี้ออกในนามบริษัท

### เกณฑ์ที่ใช้คัดรายการ

ใช้กติกาเดียวกับป๊อปอัพแจ้งเตือนรายสัปดาห์บนหน้าเว็บเป๊ะ ๆ

- **ใบนำเข้า** — อายุ 6 เดือนนับจากวันที่ออก · แจ้งเตือนเมื่อหมดอายุแล้ว หรือเหลือไม่เกิน 30 วัน
- **ใบนำออก** — อายุ 1 เดือนนับจากวันที่นำออก · แจ้งเตือนเมื่อหมดอายุแล้วหรือเหลือไม่เกิน 7 วัน
  ตารางแสดงเฉพาะสองสถานะนี้เท่านั้น ใบที่อายุยังปกติจะไม่ถูกนำมาแสดง แม้จะเลยกำหนดยื่นต่อ กสทช. แล้วก็ตาม
  (กำหนดยื่น = วันหมดอายุ − 15 วัน แสดงเป็นคอลัมน์เพิ่มเติมของแถวที่เข้าเกณฑ์)

> **ข้อควรทราบเรื่องกำหนดยื่น กสทช.** เมื่อตารางแสดงเฉพาะใบที่หมดอายุแล้วหรือเหลือไม่เกิน 7 วัน
> ในขณะที่กำหนดยื่นอยู่ที่ 15 วันก่อนหมดอายุ ใบอนุญาตที่ปรากฏในรายงานจึงเลยกำหนดยื่นไปแล้วเสมอ
> หากต้องการให้รายงานเตือน *ก่อน* ถึงกำหนดยื่น ให้ตั้ง `WEEKLY_ALERT_EXPORT_WITHIN_DAYS=20`
> ใบที่เหลืออายุ 16–20 วันก็จะเข้ามาอยู่ในตารางตั้งแต่ยังยื่นทัน
- ใบที่ผู้ใช้กด **“ทำเครื่องหมายเสร็จสิ้น”** แล้ว จะหยุดนับวันและไม่เข้ารายงาน

## 2. ตั้งค่าใน `backend/.env`

> **ระบบเขียนจดหมายเองได้ แต่ส่งเองไม่ได้ถ้าไม่มีช่องทาง**
>
> การประกอบจดหมาย (ดึงข้อมูล เขียนเนื้อความ ทำตาราง แนบ CSV) เป็นงานที่ระบบทำเองทั้งหมด
> แต่การ **ส่ง** ต้องผ่านเซิร์ฟเวอร์เมลเสมอ ไม่มีวิธีที่โปรแกรมจะยิงจดหมายเข้ากล่อง Outlook
> ได้โดยตรงโดยไม่ผ่านตัวกลาง เลือกช่องทางจาก 5 แบบด้านล่าง

### แบบที่ 0 — ยืม Outlook บนเครื่องเป็นคนส่ง (ไม่ต้องใช้รหัสผ่าน)

```env
MAIL_PROVIDER=outlook
WEEKLY_ALERT_TO=theeparat.metheepooriwat@kobelco.com
MAIL_OUTLOOK_DISPLAY_ONLY=false
```

ถ้าเครื่องที่รัน backend เป็น Windows และมี Outlook ล็อกอินค้างไว้อยู่แล้ว
ระบบจะเขียนจดหมาย ใส่ผู้รับ แนบ CSV แล้ว**กดส่งให้เอง**ผ่านบัญชีนั้น
ไม่ต้องมี `SMTP_PASSWORD` ไม่ต้องขอ App password ไม่ต้องรอ IT

เหมาะที่สุดสำหรับกรณี "ส่งหาตัวเอง" — บัญชีที่ล็อกอิน Outlook อยู่จะเป็นทั้งผู้ส่งและผู้รับ

| ต้องมี | รายละเอียด |
| --- | --- |
| ระบบปฏิบัติการ | Windows (backend ต้องรันบนเครื่องเดียวกับ Outlook) |
| Outlook | ติดตั้งแล้ว และตั้งโปรไฟล์บัญชีเรียบร้อย (เปิดโปรแกรมแล้วเห็นกล่องจดหมาย) |
| PowerShell | มีมากับ Windows อยู่แล้ว ระบบใช้สั่งงาน Outlook |

ตั้ง `MAIL_OUTLOOK_DISPLAY_ONLY=true` ถ้าอยากให้เปิดหน้าต่างร่างจดหมายขึ้นมาให้ตรวจก่อน
แล้วกด Send เอง แทนที่จะส่งออกเลย

**ตรวจก่อนว่าเครื่องพร้อมไหม** — รันสคริปต์นี้ใน PowerShell ก่อนเปิด backend

```powershell
cd backend
powershell -ExecutionPolicy Bypass -File .\check-outlook.ps1
```

ถ้าผ่าน จะมีเมลทดสอบเข้ากล่องจดหมาย 1 ฉบับ ถ้าไม่ผ่านสคริปต์จะบอกว่าติดตรงไหน

> **ข้อจำกัด** วิธีนี้ผูกกับเครื่องคน ถ้าปิดเครื่องหรือปิด Outlook ไว้ จดหมายจะไปค้างที่ Outbox
> จนกว่าจะเปิดใหม่ ถ้าจะย้าย backend ขึ้นเซิร์ฟเวอร์จริงให้เปลี่ยนไปใช้ `graph` หรือ `smtp`

### แบบที่ 0.5 — เขียนลงไฟล์ ไม่ต้องมีบัญชีเมล

```env
MAIL_PROVIDER=file
MAIL_OUT_DIR=outbox
```

ระบบจะเขียนจดหมายฉบับเต็มลงโฟลเดอร์ `backend/outbox/` ครั้งละ 2 ไฟล์

| ไฟล์ | เปิดยังไง |
| --- | --- |
| `weekly-alert-<วันเวลา>.eml` | ดับเบิลคลิกเปิดด้วย Outlook ได้เลย เห็นทั้งหัวจดหมาย ผู้รับ และไฟล์แนบ |
| `weekly-alert-<วันเวลา>.html` | เปิดด้วยเบราว์เซอร์ เห็นเฉพาะเนื้อจดหมาย |

ไม่ต้องมีรหัสผ่าน ไม่ต้องขอ IT ใช้ดูว่าระบบเขียนอะไรออกมาก่อนตัดสินใจเปิดส่งจริง
ไฟล์ `.eml` ที่ได้ ถ้าอยากส่งให้ตัวเองก็ลากเข้า Outlook แล้วกดส่งต่อได้เลย

### แบบที่ 1 — ส่งผ่าน SMTP ของ Microsoft 365 (ตั้งง่ายที่สุด)

```env
MAIL_PROVIDER=smtp
MAIL_FROM=iconfirm@kobelco.com
MAIL_FROM_NAME=I-CONFIRMATION System

SMTP_HOST=smtp.office365.com
SMTP_PORT=587
SMTP_STARTTLS=true
SMTP_USERNAME=iconfirm@kobelco.com
SMTP_PASSWORD=<รหัสผ่านของกล่องจดหมายที่ใช้ส่ง>
```

> **สิ่งที่ต้องขอจากทีม IT ก่อน**
> Microsoft 365 ปิด SMTP AUTH ไว้เป็นค่าเริ่มต้น ต้องให้ผู้ดูแล Microsoft 365 เปิด
> *Authenticated SMTP* ให้กล่องจดหมายที่ใช้ส่ง (Microsoft 365 admin center →
> Users → เลือกบัญชี → Mail → Manage email apps → ติ๊ก Authenticated SMTP)
> และถ้าบัญชีเปิด MFA ไว้ ต้องใช้ **App password** แทนรหัสผ่านปกติ

**ถ้าบริษัทมี SMTP relay ภายในอยู่แล้ว** ที่ยอมให้เครื่องเซิร์ฟเวอร์ส่งได้โดยไม่ต้องล็อกอิน
ก็เว้น `SMTP_USERNAME` และ `SMTP_PASSWORD` ว่างทั้งคู่ แล้วชี้ไปที่ relay แทน

```env
MAIL_PROVIDER=smtp
MAIL_FROM=iconfirm@kobelco.com
SMTP_HOST=relay.kobelco.internal
SMTP_PORT=25
SMTP_STARTTLS=false
```

วิธีนี้ไม่ต้องใช้รหัสผ่านของใครเลย แต่ต้องให้ทีมเน็ตเวิร์กอนุญาต IP ของเครื่องเซิร์ฟเวอร์ที่ relay ก่อน
**หมายเหตุ:** `smtp.office365.com` บังคับล็อกอินเสมอ ใช้วิธีนี้กับ host นั้นไม่ได้

### แบบที่ 2 — ส่งผ่าน Microsoft Graph API (องค์กรที่ปิด Basic Auth แล้ว)

```env
MAIL_PROVIDER=graph
GRAPH_TENANT_ID=<Directory (tenant) ID>
GRAPH_CLIENT_ID=<Application (client) ID>
GRAPH_CLIENT_SECRET=<Client secret>
GRAPH_SENDER=iconfirm@kobelco.com
```

ขั้นตอนฝั่ง Azure — สร้าง App registration แล้วให้สิทธิ์แบบ **Application permission**
`Mail.Send` จากนั้นกด **Grant admin consent**
แนะนำให้จำกัดสิทธิ์ด้วย *Application Access Policy* ให้ส่งได้เฉพาะกล่องจดหมายของระบบเท่านั้น

วิธีนี้ **ไม่ใช้รหัสผ่านของคน** ใช้ client id/secret ของแอปแทน จึงเหมาะที่สุดสำหรับระบบที่ส่งเมลเอง
และเป็นทางเดียวที่ใช้ได้ถ้าองค์กรปิด Basic Auth ไปแล้ว

### แบบที่ 3 — เขียนลง log อย่างเดียว

```env
MAIL_PROVIDER=log
```

ไม่ส่ง ไม่เก็บไฟล์ เขียนลง log แค่บรรทัดเดียวว่าจะส่งถึงใคร หัวข้ออะไร
ถ้าอยากเห็นตัวจดหมายจริงให้ใช้ `MAIL_PROVIDER=file` แทน

## 3. ตั้งรอบเวลา

```env
WEEKLY_ALERT_ENABLED=true
WEEKLY_ALERT_TO=theeparat.metheepooriwat@kobelco.com
WEEKLY_ALERT_DAY=MON        # SUN / MON / TUE / WED / THU / FRI / SAT
WEEKLY_ALERT_TIME=08:30     # เวลาแบบ 24 ชั่วโมง
WEEKLY_ALERT_TZ=Asia/Bangkok
```

ตัวจับเวลาวนเช็คทุก 1 นาที และกันส่งซ้ำด้วยเลขสัปดาห์มาตรฐาน ISO-8601 (เช่น `2026-W36`)
ที่บันทึกไว้ในตาราง `weekly_alert_logs` — **ต่อให้รีสตาร์ท backend กี่รอบในสัปดาห์เดียวกัน
อีเมลรอบอัตโนมัติก็จะออกแค่ฉบับเดียว**

ถ้าเซิร์ฟเวอร์ดับคร่อมเวลาส่งพอดี ระบบจะส่งย้อนหลังให้ทันทีที่เปิดเครื่อง (ภายในสัปดาห์เดิม)
ปิดพฤติกรรมนี้ได้ด้วย `WEEKLY_ALERT_CATCH_UP=false`

ค่าอื่น ๆ ทั้งหมดดูได้ที่ `backend/.env.example`

### ส่งทันทีตอนเปิดเซิร์ฟเวอร์

ค่าเริ่มต้นคือเปิดไว้ — ทุกครั้งที่ backend เริ่มทำงาน ถ้าสัปดาห์นั้น**ยังไม่ได้ส่ง**
ระบบจะดึงข้อมูลจริงจากฐานข้อมูล เขียนอีเมล แล้วส่งออกทันที 1 ฉบับ ถึงผู้รับใน `WEEKLY_ALERT_TO`
โดยไม่ต้องรอถึงเช้าวันจันทร์

```env
WEEKLY_ALERT_SEND_ON_START=true
```

นับเป็นการส่งแบบ `AUTO` และบันทึก `WeekKey` ลงตาราง `weekly_alert_logs`
จึงยังคุมไว้ที่ **สัปดาห์ละ 1 ฉบับ** — รีสตาร์ท backend กี่รอบในสัปดาห์เดียวกันก็ไม่ส่งซ้ำ
และเมื่อส่งไปแล้ว รอบวันจันทร์ของสัปดาห์นั้นจะถูกข้ามไปเอง

ตั้งเป็น `false` ถ้าอยากให้รอถึงรอบวันจันทร์อย่างเดียว

### อยากให้ส่งซ้ำในสัปดาห์เดิม (ตอนแก้เนื้อจดหมาย)

```env
WEEKLY_ALERT_FORCE_SEND_ON_START=true
```

ข้ามตัวกันส่งซ้ำไปเลย รีสตาร์ท backend ทีก็ได้เมลใหม่ที ไม่ต้องไปลบแถวในตาราง
**แก้เสร็จแล้วเปลี่ยนกลับเป็น `false`** ไม่งั้นทุกครั้งที่รีสตาร์ทจะมีเมลออกไปหาผู้รับ

ถ้าอยากลบประวัติออกจริง ๆ ก็ยิง SQL ตรงได้

```sql
DELETE FROM weekly_alert_logs WHERE week_key = '2026-W37';
```

## 4. ไม่มีหน้าเว็บและไม่มี API

ส่วนนี้ทำงานเบื้องหลังล้วน ๆ ไม่มีเมนู ไม่มีหน้าตรวจสอบ และไม่มี endpoint ให้เรียก

การตั้งค่าทั้งหมดอยู่ที่ `.env` ของ backend ส่วนผลการส่งดูได้จาก log ของเซิร์ฟเวอร์
(`[weekly-alert] ✅ ...`) หรือจากตาราง `weekly_alert_logs` ในฐานข้อมูลโดยตรง

## 5. โครงสร้างโค้ด

```
backend/
├── mailer/                      แพ็กเกจส่งอีเมล (ใช้ไลบรารีมาตรฐาน Go ล้วน ไม่เพิ่ม dependency)
│   ├── config.go                อ่านค่าตั้งจาก .env + คำนวณรอบส่งถัดไป
│   ├── report.go                โครงสร้างข้อมูลรายงาน + จัดรูปแบบวันที่ไทย + หัวข้ออีเมล
│   ├── render.go                ประกอบอีเมล HTML และฉบับข้อความล้วน
│   ├── xlsx.go                  สร้างไฟล์ Excel แนบ (เขียน OOXML เอง ไม่พึ่งไลบรารีนอก)
│   ├── csv.go                   สร้างไฟล์ CSV แนบ (ทางเลือกสำรอง)
│   ├── message.go               ประกอบจดหมาย MIME (multipart + เข้ารหัสหัวข้อภาษาไทย)
│   ├── send.go                  ส่งจริงผ่าน SMTP / Microsoft Graph / เขียนลงไฟล์
│   ├── send_outlook.go          ส่งผ่าน Outlook บนเครื่อง Windows (ไม่ต้องใช้รหัสผ่าน)
│   ├── render_test.go           เทสต์เนื้อจดหมายและไฟล์แนบ
│   └── send_test.go             เทสต์ช่องทางส่ง (file / SMTP validation)
├── controllers/weekly_alert.go  รวบรวมข้อมูลจากฐานข้อมูล + ประกอบและส่งอีเมล
├── jobs/weekly_alert.go         ตัวจับเวลาส่งอัตโนมัติ
└── models/weekly_alert_log.go   ตารางบันทึกการส่ง (ใช้กันส่งซ้ำ สัปดาห์ละ 1 ฉบับ)
```

ฝั่ง frontend ไม่มีไฟล์เกี่ยวข้องแล้ว — ส่วนนี้ทำงานเบื้องหลังทั้งหมด

รันเทสต์เฉพาะส่วนนี้

```bash
cd backend && go test ./mailer/...
```

## 6. แก้ปัญหาที่พบบ่อย

| อาการ | สาเหตุและวิธีแก้ |
| --- | --- |
| `ยังไม่ได้ตั้ง SMTP_USERNAME / SMTP_PASSWORD` | ยังไม่ได้บอกระบบว่าจะส่งผ่านช่องทางไหน — ถ้ารันบน Windows ที่มี Outlook ให้ตั้ง `MAIL_PROVIDER=outlook` ได้เลย |
| `MAIL_PROVIDER=outlook ใช้ได้เฉพาะ...Windows` | backend รันอยู่บน Linux/Docker — วิธีนี้ต้องรันบนเครื่องเดียวกับ Outlook ถ้าย้ายขึ้นเซิร์ฟเวอร์แล้วให้ใช้ `graph` |
| ตั้ง outlook แล้วเมลไปค้างที่ Outbox | Outlook ปิดอยู่หรือยังไม่ได้ซิงก์ — เปิด Outlook ทิ้งไว้ จดหมายจะออกเอง |
| `เข้าสู่ระบบเมลไม่สำเร็จ` | กล่องจดหมายยังไม่ได้เปิด Authenticated SMTP หรือบัญชีเปิด MFA แล้วยังใช้รหัสผ่านปกติ — ต้องใช้ App password |
| `เซิร์ฟเวอร์ไม่รับผู้ส่ง` | `MAIL_FROM` ไม่ตรงกับบัญชีที่ล็อกอิน — Microsoft 365 บังคับให้ตรงกัน (หรือได้รับสิทธิ์ Send As) |
| `เชื่อมต่อเซิร์ฟเวอร์เมลไม่สำเร็จ` | ไฟร์วอลล์ปิดขาออกพอร์ต 587 — ขอทีมเน็ตเวิร์กเปิดให้เครื่องเซิร์ฟเวอร์ |
| ไม่มีอีเมลเข้าเลย ทั้งที่ log ว่าส่งสำเร็จ | ลองดูใน Junk Email แล้วเพิ่มผู้ส่งเป็น safe sender |
| เวลาส่งเพี้ยนไปจากที่ตั้ง | เครื่อง/คอนเทนเนอร์ไม่มี tzdata — ระบบจะ fallback เป็น UTC+7 ให้อัตโนมัติ แต่ควรลง `tzdata` เพื่อความถูกต้อง |
| อยากเปลี่ยนผู้รับ | แก้ `WEEKLY_ALERT_TO` ใน `.env` แล้วรีสตาร์ท backend |
| อยากส่งใหม่ในสัปดาห์เดิม | ตั้ง `WEEKLY_ALERT_FORCE_SEND_ON_START=true` แล้วรีสตาร์ท backend (หรือลบแถวของ `week_key` นั้นในตาราง `weekly_alert_logs`) |
